# Source completeness and lifecycle controls

REST collections now distinguish exhausting a safety budget from reaching the source's declared end. Comments, repository catalogs and directory listings raise `IncompleteSource` if they exceed page/item/deadline limits or contain unsupported page structures. Jira comment offsets/totals and comment identities must remain consistent. Jira Cloud search continuations require coherent terminal markers and cannot repeat. Data Center continuation offsets must advance with explicit boolean completion markers.

Search methods intentionally return a bounded prefix up to their `max_results` argument; that is not a claim to enumerate every issue/code match. A page-budget failure before satisfying that requested prefix raises an error and requires a narrower query. Source ACL visibility and the upstream server's own completeness declarations still require live qualification.

The operator-owned adapter configuration accepts `max_pages` (default 10, maximum 100), `max_collection_items` (default/maximum 10,000) and `collection_timeout_s` (default 60, range 1–300). A collection shares an absolute HTTP deadline across its pages/retries. Existing per-request, retry/cooldown and response-byte controls also apply; a lower request ceiling cannot be extended by a collection. A blocking socket read can take its configured timeout to terminate. These limits do not establish production throughput or eight-hour soak behavior.

Bitbucket Cloud `next` URLs must retain the approved resource path and original query scope. Only the existing query keys plus `page`/`pagelen` are accepted; repeated/invalid continuations, enlarged page sizes and cross-resource/origin jumps are refused. An API/server needing another pagination contract requires an explicit reviewed mapping, not a guessed fallback. Repository context requires an observed default branch or explicit ref. An unavailable Data Center default-branch endpoint may be treated as unsupported only on 404; authorization/transport failures propagate.

Jira attachments are never sliced to fit a limit. Declared/observed sizes must match and fit the byte budget, and the returned complete content has an observed SHA-256. Text attachments and repository text reads support strict UTF-8; unsupported decoding requires source review instead of inserting replacement characters. Repository text reads also reject NUL-containing binary payloads. Binary attachments are not converted to text automatically. Repository README context explicitly marks a 4,000-character excerpt and retains the full bounded text's hash. Directory pagination completion is recorded separately. `resolved_commit: null` is deliberate: a requested branch/ref and observed text hash do not certify an immutable upstream commit.

Every REST request/retry and MCP protocol exchange rechecks the current worker lease/caller, with additional checks while consuming streaming responses. JSON/transport validation must preserve native fencing exceptions. Source HTTP/MCP intents and linked outcomes include generated request IDs and bind to the current job's run when present; query/body/credential values are omitted. Missing outcomes remain uncertain. Audit backpressure also stops further protocol requests. MCP metadata traffic needs application read policy as well as operator-approved endpoint configuration. A previously dispatched request cannot be undone by revocation; no new phase/page/retry should follow it after authority is lost.

Legacy unattended evaluation grants remain restricted to synthetic fixture sources. A synthetic SUT alone cannot make a real adapter or classified organization source eligible for those grants. Organization regression suites/scheduling need a separate versioned grant and qualification design.

The tests use synthetic local/mock transports, including pagination exhaustion, repeated identities/cursors, missing completion markers, query/resource jumps, byte/decode mismatches, README excerpts, actor revocation during responses/retries and MCP initialization/read chains. They do not prove actual Jira/Bitbucket tenant ACLs, full native hosted payload mappings, upstream commit/field version support, interactive OAuth, organization model-data approval or production cleanup. The read-only contract remains; write-back needs a separately reviewed capability.
